## 单一用途描述 \*

> 扩展必须具有明确且易于理解的单一用途。

本扩展仅用于**多邮箱（163 / QQ / USTC / Gmail）未读邮件的后台静默检查与桌面提醒**：
在用户授权登录的邮箱会话基础上，后台定时检测各邮箱新邮件并在本地弹出桌面通知，
全程在本机完成，不对外上传任何邮件数据。用户点击通知或按钮后仅在被授权前提下
打开对应邮箱；自动定时检查绝不自动打开或常驻任何邮箱标签页。

## 权限理由

> 权限均为实现上述单一用途所必需，无多余越权请求；已移除所有与该单一功能无关的权限。

### alarms 理由 \*

`chrome.alarms` 用于在后台**定时触发**各邮箱的未读邮件检查，是 MV3 下 Service Worker
实现周期任务的唯一受支持机制。无该权限则无法实现“自动定时提醒”这一核心功能。
触发路径为纯后台 API 调用，绝不会因定时触发而新建或导航任何浏览器标签页。

### storage 理由 \*

使用 `chrome.storage.local` 在本地持久化会话令牌（sid）、各邮箱未读数与上次检查状态、
以及捕获的 API 请求模式。数据仅存于用户本机浏览器，不上传服务器；用于在后台无页面时
复现真实 API 读取未读数。这是后台静默检查所必需的最小平稳存储。

### notifications 理由 \*

用于在有新邮件时向用户弹出**本地桌面通知**，是“新邮件提醒”这一单一用途的直接体现。
通知仅本地展示，内容为未读数摘要，不包含邮件正文，不请求后台推送或远程服务器。

### tabs 理由 \*

仅用于**识别并复用用户已经手动打开的邮箱标签页**（如读取其状态、在用户点击时定位到
对应标签），以及在用户于 Popup/Options 界面主动点击“打开邮箱/同步会话”时打开目标邮箱。
扩展**从不**在定时检查等自动路径下自动创建或导航标签页，也不会为自动检查常驻/保活任何邮箱标签
（严格对齐项目 AGENTS 规则 1）。

### cookies 理由 \*

用于在用户本机发起邮箱未读数 API 请求时，自动附带该域名的会话 Cookie（`credentials: 'include'`），
以便在无需重新登录的情况下读取未读数。Cookie 仅在本机请求中使用，不外传、不上传第三方。

### scripting 理由 \*

用于向**用户已打开的邮箱页面**注入一段轻量脚本，提取浏览器会话所需的 sid/API 格式，
作为混合检查模式的兜底回退手段。仅在页面存在且需要时注入，不用于跟踪或采集页面内容，
不读取与邮件检查无关的页面数据。

### declarativeNetRequest 理由 \*

用于在**会话级**对指向已授权邮箱域名（163/QQ/USTC/Gmail）的探测请求修正请求头与
Cookie 附加，保证后台无页面时也能按真实会话格式发起未读检查。规则仅限本扩展声明的
最小邮箱域集合，不拦截、不改写其他任意网站流量。

### identity 理由 \*

用于 Gmail 官方 OAuth2 授权（`gmail.readonly` 只读 scope），在用户主动授权下获取访问
Gmail 未读元数据的只读权限。仅申请 `gmail.readonly` 只读范围，无发送、无删除、无全量读取权限。
相关 `client_id` 为 Google OAuth 公开标识，非密钥。

### 主机权限理由 \*

主机权限严格限定为实现多邮箱检查所必需的最小域集合：

- `https://mail.163.com/*`、`https://*.163.com/*` —— 163 邮箱
- `https://mail.qq.com/*`、`https://*.qq.com/*` —— QQ 邮箱
- `http://mail.ustc.edu.cn/*`、`https://mail.ustc.edu.cn/*` —— 中科大邮箱
- `https://gmail.googleapis.com/*` —— Gmail 官方 API

仅请求这几个已声明邮箱域，不申请 `<all_urls>` 或任意站点的匹配模式，无与邮件检查无关的主机访问。

## 你在使用远程代码吗? \*

**否。**

本扩展所有 JavaScript / 资源（JS、Wasm、图标等）均**随扩展包一起打包发布**，
不引用任何外部 `<script>`、外部模块文件，也不通过 `eval()` / `new Function()` 求值字符串。
manifest 的 `content_security_policy` 保持 `script-src 'self'`，代码明文、可审查、无远程加载。

### 理由 \*

扩展完全离线、自包含运行：全部探测、拦截、Gmail OAuth2、通知、定时逻辑均在本地执行，
包内不含也不依赖任何外部脚本或 Wasm；`extension_pages` 的 CSP 为 `script-src 'self'; object-src 'self'`，
从机制上杜绝了远程代码注入，便于商店审查且更安全。

## 数据使用量

> 此部分将公开显示在商品详情页，请与本扩展在 `doc/PRIVACY.md` 的披露保持一致。

你计划现在或将来从用户处收集哪些用户数据?

**收集的最少必要数据（均仅本机处理、不对外上传）：**

1. **认证信息 / Cookie / 会话令牌（sid）**：用户授权登录后，本地保存用于后台读取未读数的会话令牌
   （163/QQ/USTC 的 sid 与 Gmail 的 OAuth2 访问令牌）。仅用于向对应邮箱读取未读数。
2. **用户内容（未读元数据，非正文）**：各邮箱未读数量与触发提醒所需的最小元信息，用于生成桌面通知，
   不含邮件正文、联系人、通讯录等敏感内容。

**明确不收集 / 不上传：**

- 不收集邮件正文、附件、搜索/浏览历史、位置、联系人；
- 不在任何服务器端存储、分析或中转数据；所有数据仅存在于用户本机浏览器的 `chrome.storage.local` 与浏览器会话中；
- 不出售用户数据，不用于广告、行为画像或任何第三方共享。

**数据删除**：用户在 Popup/Options 中清除数据或卸载扩展、清空浏览器存储后，本地数据即被删除；无服务器副本。
