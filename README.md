# 浏览器邮箱插件（Edge Mail Notifier）

- Microsoft Edge 浏览器插件（MV3）
- 支持 163 / QQ / Gmail / USTC 等邮箱
- 支持邮件检查、未读计数、桌面通知、快速跳转邮件
- 混合方案：内容脚本提取会话 + SW 独立 API 检查

## 核心架构：混合检查模式

本项目采用「混合检查模式」：以 **SW 后台 API + 持久化 sid** 为核心方案，
以**内容脚本读取邮箱网页未读数**为可靠补充，**检查失败时自动恢复会话**，
通过短暂打开后台邮箱标签同步 sid（10 分钟冷却控制、读取后自动关闭）。

```
┌─────────────────────────────────────────────────────────────────────┐
│                      v0.8.0 混合模式检查流程                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  SW 定时触发（每 N 分钟）                                            │
│       │                                                             │
│       ▼                                                             │
│  ① SW API 直调（带持久化缓存 sid + Cookie）                          │
│       ├── ✅ 读到未读数 → 更新 badge + 通知                           │
│       └── ❌ 无有效 sid 或 API 失败                                    │
│             │                                                       │
│             ▼                                                       │
│  ② 查已打开的邮箱标签 → 有则用内容脚本读未读（不新开标签）              │
│       ├── ✅ 读到未读数 → 更新 badge + 通知                           │
│       └── ❌ 无标签                                                   │
│             │                                                       │
│             ▼                                                       │
│  ③ 自动打开后台邮箱标签恢复会话（active:false 不抢焦点）               │
│       │     —— 用户手动检查 → 不受限直接恢复                          │
│       │     —— alarm 定时检查 → 受 10 分钟冷却控制                     │
│       ├── ✅ 读到未读数 + 缓存 sid → 自动关闭标签 → 更新 badge          │
│       └── ❌ 仍失败（邮箱未登录等）→ 标记需手动同步                      │
│                                                                     │
│  手动检查（Popup/Options 点击）→ 打开邮箱标签同步 sid → 自动关闭        │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

> 说明：定时检查失败时**会自动短暂打开后台邮箱标签恢复会话**（active:false 不抢焦点，
> 读取到未读数后立即自动关闭），无需用户手动操作。
> 10 分钟冷却期控制避免反复弹标签打扰用户。
> 当 sid 过期且用户未打开邮箱时，自动检查会标记「需手动同步」，不会打扰用户。

### 为什么需要「混合」而不是纯内容脚本？

| 方案 | 需常驻邮箱页 | 定时后台检查 | 可见标签干扰 | 可靠度 | 说明 |
|------|------------|------------|------------|--------|------|
| **混合模式（当前 v0.8.0）** | ❌ 不需要（sid持久化7天） | ✅ | ❌ 不打开 | ⭐⭐⭐⭐ | SW API为主 + 内容脚本补充，自动恢复会话受冷却控制，仅需时短暂开标签 |
| 纯内容脚本 | ✅ 需要 | 仅页面存活时 | 无 | ⭐⭐⭐⭐ | DOM 读取最可靠，但需常驻页面 |
| 纯 SW API | ❌ | ✅ | 无 | ⭐⭐ | 依赖 sid 有效性，sid 过期即失效 |

### 关键流程（授权 → 获取未读数）

1. **授权（一次）**：浏览器打开并登录 `mail.163.com` / `mail.qq.com`
2. **同步会话**：Options → 点「🔑 授权·同步会话」→ 扩展后台打开邮箱页提取 sid → 缓存至本地 → 关闭标签
3. **日常使用**：SW 每 N 分钟检查 → SW API + 缓存 sid → badge + 通知
4. **sid 过期后**：自动检查失败 → **自动短暂打开后台邮箱标签恢复会话** → 读取到未读数后自动关闭
   - 若恢复成功 → 自动检查正常完成，无需用户干预
   - 若恢复失败（邮箱未登录等）→ 标记需手动同步
5. **手动检查**：Popup → 「🚀 运行全量检查」→ 打开邮箱标签同步会话 → 读取后自动关闭

> **说明**：自动检查失败时会自动打开后台邮箱标签恢复会话（active:false 不抢焦点），
> 读取到未读数或 sid 后立即自动关闭。自动恢复受 10 分钟冷却控制，避免频繁打扰用户。
