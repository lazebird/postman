# 浏览器邮箱插件（Edge Mail Notifier）

- Microsoft Edge 浏览器插件（MV3）
- 支持 163 / QQ / Gmail / USTC 等邮箱
- 支持邮件检查、未读计数、桌面通知、快速跳转邮件
- 混合方案：内容脚本提取会话 + SW 独立 API 检查

## 核心架构：混合检查模式

本项目采用「混合检查模式」：以**内容脚本读取邮箱网页未读数**为可靠主干，
以 **SW 后台 API** 为可选兜底，并在用户未开邮箱页时**自动保活一个隐藏的后台邮箱标签**作为数据源，
从而在**用户标签页关闭的状态下仍能全量检查与定时自动检查**：

```
┌─────────────────────────────────────────────────────────────────────┐
│                      v0.6.0 混合模式检查流程                          │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  SW 定时 / 全量 / 手动触发                                           │
│       │                                                             │
│       ▼                                                             │
│  找已打开的邮箱标签 → 有则复用，无则自动开一个后台邮箱标签                 │
│       │                                                             │
│       ▼                                                             │
│  内容脚本注入(同源 in-origin) → 读取真实未读数 + 提取 sid → 缓存         │
│       │                                                             │
│       ├── ✅ 读到未读数 → 更新 badge + 桌面通知                        │
│       ├── ✅ 只拿到 sid（落在辅助页）→ 视为已授权，导航到收件箱再读       │
│       └── ❌ 邮箱未登录 → 提示用户登录邮箱一次                            │
│             │                                                       │
│             └── hybrid 兜底：内容脚本读不到时才用缓存 sid 调 SW API       │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

> 说明：国内 webmail（163/QQ）的“未读读取”只有在与网页**同源**的内容脚本里才稳定可靠
> （登录 Cookie 是第一方、sid 由页面 JS 动态生成）；SW 跨源直调其内部 API 多轮实测并不稳定。
> 因此本版将“自动保活一个隐藏后台邮箱标签 + 内容脚本读取”作为主线，用户在**关闭邮箱标签**后，
> 扩展也会自己开后台标签完成检查，不再依赖用户手动保留邮箱页。


### 为什么需要「混合」而不是纯内容脚本？

| 方案 | 需常驻邮箱页 | 定时后台检查 | 可靠度 | 说明 |
|------|------------|------------|--------|------|
| **混合模式（当前 v0.6.0）** | ✅（自动保活一个隐藏邮箱标签） | ✅ | ⭐⭐⭐⭐ | 内容脚本读取未读为主，SW API 为兜底 |
| 纯内容脚本 | ✅ 需要 | 仅页面存活时 | ⭐⭐⭐⭐ | DOM 读取最可靠，但需常驻页面 |
| 纯 SW API | ❌ | ✅ | ⭐⭐ | 依赖 sid 有效性，sid 过期即失效 |

### 关键流程（授权 → 获取未读数）

1. **授权（一次）**：浏览器打开并登录 `mail.163.com` / `mail.qq.com`
2. **同步会话**：Options → 点「🔑 授权·同步163会话」→ 扩展打开邮箱页 → 内容脚本提取会话令牌 sid 并缓存 → 显示「已授权 ✅」
3. **获取未读数**：在邮箱中打开左侧「收件箱」主页面 → 点「📥 获取未读数·163」→ 读出未读数（与网页一致）
4. **日常使用**：SW 每 N 分钟（或手动/全量）检查 → 自动保活邮箱后台标签 → 内容脚本读取未读数 → badge + 通知
5. **邮箱未登录**：自动打开邮箱后被重定向到登录页时，提示用户登录一次后即可自动检查

> **提示**：若「获取未读数」返回为空，多半是扩展落在了联系人等辅助页面——请确认当前停留的是邮箱「收件箱」主页面后再读取。

## 数据持久化与存储分层

| 存储区 | 存放的数据 | 插件更新时 |
|--------|-----------|-----------|
| `chrome.storage.local`（持久化） | 账号配置、用户设置、检查历史 | ✅ **保留** |
| `chrome.storage.session`（会话级） | sid 会话令牌（12小时TTL）、调试日志 | ⚠️ 清空，可重新同步 |
