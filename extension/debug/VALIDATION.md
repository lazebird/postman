# 方案 B PoC — 真实环境验证计划

> 本文档描述在实际浏览器 + 真实邮箱登录环境中验证方案 B 可行性的步骤与判断标准。

## 验证目标

| 验证项 | 说明 |
|--------|------|
| **1. 扩展可正常加载** | MV3 manifest 配置正确，SW 可启动 |
| **2. 163 接口可用** | 在已登录 mail.163.com 的浏览器中，SW fetch 能返回未读数 |
| **3. QQ 接口可用** | 在已登录 mail.qq.com 的浏览器中，SW fetch 能返回未读数 |
| **4. Cookie 跨域传递生效** | 会话 Cookie 能随扩展跨域 fetch 发送 |
| **5. 调试日志完整** | 能通过 Popup 查看到请求/响应详情 |
| **6. 定时检查可用** | chrome.alarms 能触发定时探测 |

## 验证前提

- Edge 116+ 或 Chrome 116+ 浏览器
- 至少一个可登录的 163 或 QQ 邮箱账号
- 确保在浏览器中已登录对应邮箱网页（并保持登录状态）
- 如同时验证多个邮箱，请分别登录

## 验证步骤

### Step 1：加载扩展

1. 打开 `edge://extensions/` 或 `chrome://extensions/`
2. 开启右上角 **开发者模式**
3. 点击 **加载已解压的扩展程序**
4. 选择本项目 `extension/` 目录
5. 确认扩展出现在扩展列表中且无报错

### Step 2：检查 SW 启动状态

1. 在扩展列表中点击 **Service Worker** 链接（或"检查视图"）
2. 打开 DevTools Console
3. 确认看到类似日志：
   ```
   [INFO] [service-worker] Service Worker 启动
   [INFO] [service-worker] 注册定时检查闹钟: interval=5分钟
   ```

### Step 3：登录邮箱

1. 新建标签页，访问 https://mail.163.com/
2. 登录邮箱（确保能正常看到收件箱）
3. 如需验证 QQ，同样访问 https://mail.qq.com/ 并登录

### Step 4：在 Options 中添加账户

1. 右键扩展图标 → **选项**
2. 选择提供商，填写邮箱地址
3. 点击 **添加**
4. 保持 Options 页面打开

### Step 5：运行手动探测

1. 点击扩展图标打开 **Popup**
2. 切到 **探测** 标签页
3. 点击 **探测 163**（或 **探测 QQ**）
4. 等待结果返回

### Step 6：查看结果与日志

#### 结果判定标准

**✅ 认证通过（方案 B 可行）：**
- 响应中包含未读数字段（如 `unreadCount: 3` 或邮件列表数据）
- 日志中显示 `探测成功` 或接口返回有效 JSON 且包含邮件数据
- 无 `FA_SECURITY`、无登录页面 HTML

**❌ 认证被拦截（方案 B 可能不可行）：**
- 日志显示 `被认证层拦截` 或 `FA_SECURITY`
- 返回内容为登录页面 HTML
- HTTP 状态码为 401/403

**⚠️ 接口不可用但认证正常：**
- 请求返回正常 HTTP 状态码
- 但响应中未能解析出未读数
- 可能是接口结构已变化，需调整解析规则

## 调试信息记录

### 调试数据收集

在验证过程中，请从以下位置收集调试信息：

1. **Popup → 日志** 标签页：查看请求/响应详情
2. **SW Console**：查看完整日志（含 DEBUG 级别）
3. **Popup → 探测结果**：查看接口返回的原始内容

### 需记录的关键信息

| 信息项 | 来源 |
|--------|------|
| 邮箱提供商 | 验证对象 |
| 探测接口 | Options 中选择的接口 |
| HTTP 状态码 | 日志或探测结果 |
| 响应内容（前2KB） | 日志或探测结果 |
| 是否出现 FA_SECURITY | 日志或响应内容 |
| 是否解析到未读数 | 探测结果 |
| 浏览器版本 | 浏览器关于页面 |

### 判断方案 B 是否可行

将验证结果反馈给开发者，开发者根据以下标准判断：

- **通过**：至少有一个提供商（163 或 QQ）能成功获取未读数
- **部分通过**：一个提供商成功、另一个失败（可继续针对性调查）
- **不通过**：两个提供商均被认证拦截
