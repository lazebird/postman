# 方案 B PoC — 真实环境验证计划 v2

> 本文档描述在实际浏览器 + 真实邮箱登录环境中验证方案 B 可行性的步骤与判断标准。

## 验证目标

| 验证项 | 说明 |
|--------|------|
| **1. 扩展可正常加载** | MV3 manifest 配置正确，SW 可启动 |
| **2. 163 sid 会话获取** | 从 163 邮箱入口页提取 sid（核心修复点） |
| **3. QQ sid 会话获取** | 从 QQ 邮箱入口页提取 sid |
| **4. 带 sid 的未读接口调用** | 163/QQ 接口能返回未读数 |
| **5. Cookie 跨域传递生效** | 会话 Cookie 能随扩展跨域 fetch 发送 |
| **6. 调试日志完整** | 能通过 Popup 查看会话获取与接口探测日志 |

## 验证前提

- Edge 116+ 或 Chrome 116+ 浏览器
- 至少一个可登录的 163 或 QQ 邮箱账号
- 确保在浏览器中已登录对应邮箱网页（并保持登录状态）

## 验证步骤

### Step 1：加载扩展

1. 打开 `edge://extensions/` 或 `chrome://extensions/`
2. 开启右上角 **开发者模式**
3. 点击 **加载已解压的扩展程序**
4. 选择本项目 `extension/` 目录
5. 确认扩展出现在扩展列表中且无报错

### Step 2：登录邮箱

1. 新建标签页，访问 https://mail.163.com/
2. 登录邮箱（确保能正常看到收件箱）
3. 如需验证 QQ，同样访问 https://mail.qq.com/ 并登录

### Step 3：添加账户

1. 右键扩展图标 → **选项**
2. 选择提供商，填写邮箱地址
3. 点击 **添加**
4. 保持 Options 页面打开

### Step 4：检查会话状态

1. 查看 Options 中的 **会话状态** 卡片
2. 观察 163/QQ 的登录状态

**预期结果**：
- 已登录邮箱的提供商应显示 `✅ 已登录`
- 如显示 `❌ 未登录`，点击 **刷新会话** 按钮重试

### Step 5：手动探测

1. 点击扩展图标打开 **Popup**
2. 切到 **探测** 标签页
3. 点击 **探测 163**（或 **探测 QQ**）
4. 等待结果返回

### Step 6：查看结果

#### 结果判定

**✅ 认证验证通过：**
- 探测结果中的 `session.loggedIn: true`
- `authVerified: true`
- 响应中包含未读数或 `hasResult: true`
- 日志中无 `FA_SECURITY`/登录页标记

**⚠️ 会话获取成功但接口未返回未读数：**
- `session.loggedIn: true`（Cookie 传递已证明可行）
- 但各接口 `success: false`（未解析到未读数）
- 可能是接口参数/格式问题，需要进一步逆向

**❌ 会话获取失败（方案 B 可能不可行）：**
- `session.loggedIn: false`
- 日志显示返回了登录页 HTML
- 说明 Cookie 未随跨域 fetch 发送，或浏览器阻止了该操作

## 调试信息记录

### 关键日志位置

1. **Popup → 日志** 标签页：查看请求/响应详情
2. **SW Console**：查看完整日志（含 DEBUG 级别）
3. **Options → 会话状态**：查看 sid 获取结果

### 需记录的关键信息

| 信息项 | 来源 |
|--------|------|
| 邮箱提供商 | 验证对象 |
| sid 是否获取成功 | 日志/会话状态 |
| sid 获取来源 | 日志（url/content/cache） |
| HTTP 状态码 | 日志或探测结果 |
| 响应内容（前2KB） | 日志或探测结果 |
| 是否解析到未读数 | 探测结果 |
| 浏览器版本 | 浏览器关于页面 |

## 判断方案 B 是否可行

将验证结果反馈给开发者，根据以下标准判断：

- **通过**：至少有一个提供商能成功获取 sid 且通过带 sid 的接口探测获得未读数
- **部分通过**：sid 获取成功（证明 Cookie 传递可行）但接口参数需调整
- **不通过**：sid 均获取失败，Cookie 无法在跨域 fetch 中生效
