# v0.8.0 — 调试指南

## 架构概览

```
┌──────────────────────────────────────────────────────────┐
│                v0.8.0 API 模式捕获与回放                    │
├──────────────────────────────────────────────────────────┤
│                                                          │
│ 1. 打开邮箱页面（用户偶尔操作）                              │
│    → 内容脚本注入 API 拦截器                                │
│    → 捕获页面真实 API 请求 → 存储（sid→{sid}）              │
│    → 同时提取 sid → 缓存 chrome.storage.local             │
│                                                          │
│ 2. SW 后台检查（无需页面打开）                              │
│    → 读取缓存 sid + 捕获的 API 模式                        │
│    → 使用真实请求格式 fetch → 获取未读数                     │
│                                                          │
│ 3. 失败处理（绝不自动开标签）                               │
│    → 标记「需手动同步」→ Popup/Options 提示                 │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

## 调试入口

1. **Popup → 状态 Tab**
   - 账户状态 + 未读数总和
   - 163/QQ sid 缓存状态
   - **163/QQ API 模式学习数量**

2. **Popup → 探测 Tab**
   - 获取未读数（内容脚本）
   - 手动探测 SW 接口
   - 全量检查

3. **Service Worker 控制台**
   - `edge://extensions/` → 找扩展 → 点「Service Worker」
   - 查看 API 模式捕获/回放日志

## 关键日志模式

| 日志 | 含义 |
|------|------|
| `已保存 netease_163 的 API 模式 N 条` | API 模式学习成功 |
| `发现 N 条捕获的 QQ API 模式` | 探测时发现已有学习模式 |
| `接口 captured_1 探测成功: unreadCount=8` | 捕获的 API 回放成功 |
| `从内容脚本缓存 netease_163 sid` | sid 获取并缓存成功 |
| `接口 js6_rpc_list 被认证层拦截` | 内置接口仍不适用 |
| `已尝试自动恢复但未成功` | 会话确实失效，需手动登录 |
