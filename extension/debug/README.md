# 方案 B PoC — 调试指南

本指南说明如何在本机真实环境中验证方案 B（SW 逆向 webmail 接口）的可行性。

## 核心假设

方案 B 依赖以下前提：

1. **浏览器已登录目标邮箱网页**（mail.163.com 或 mail.qq.com）
2. **扩展获取 `host_permissions`** 后，可以在 SW 中对目标域执行跨域 fetch
3. **会话 Cookie 随请求携带**，并能在 Service Worker 的跨域 fetch 中生效
4. **能从邮箱页面/接口获取会话 sid**，再使用 sid 访问内部未读接口

## 探测流程

```
1. 获取会话 sid
   ├── 先从 chrome.storage.session 读取缓存（30分钟有效）
   ├── 无缓存 → 访问邮箱入口页面（带 credentials: 'include'）
   │   ├── 从重定向 URL 提取 sid
   │   └── 或从页面内容中提取 sid
   └── 成功 → 缓存 sid，继续后续步骤
       失败 → 返回 needsAuth=true（未登录或 Cookie 未生效）

2. 使用 sid 调用未读接口
   ├── 163: GET/POST mail.163.com/js6/s?func=...&sid=<sid>
   └── QQ: GET mail.qq.com/cgi-bin/...?sid=<sid>

3. 解析响应中的未读数
```

## 使用步骤

### 1. 加载扩展

1. 打开 Edge/Chrome 浏览器
2. 进入 `edge://extensions/` 或 `chrome://extensions/`
3. 开启 **开发者模式**
4. 点击 **加载已解压的扩展程序**
5. 选择 `extension/` 目录

### 2. 登录邮箱

在浏览器中分别登录需要验证的邮箱网页：

- 163：https://mail.163.com/
- QQ：https://mail.qq.com/

确保登录后能正常看到收件箱和未读数。

### 3. 添加账户

1. 右键扩展图标 → 选项，或点击 Popup 中的"打开设置"
2. 选择邮箱提供商
3. 输入邮箱地址（用于标识账户）
4. 点击"添加"

### 4. 验证

#### 方式一：通过 Popup 手动探测

1. 点击扩展图标打开 Popup
2. 切换到"探测"标签页
3. 点击 **刷新会话**（如果之前探测失败过，先清除旧会话）
4. 点击"探测 163"或"探测 QQ"
5. 观察探测结果中的 `session` 字段

#### 方式二：通过 Options 查看会话状态

1. 打开设置页面
2. 查看 **会话状态** 卡片，了解 163/QQ 的登录状态
3. 点击 **刷新会话** 重新获取 sid

#### 方式三：查看调试日志

1. Popup 中切换到"日志"标签页
2. 查看最新的请求/响应日志
3. 日志级别可在设置中调整为 DEBUG 查看最详细信息

### 5. 判断结果

#### ✅ 会话获取成功 + 未读探测成功

```
provider-163: INFO 开始探测163邮箱未读接口
session:163: INFO 成功获取 163 sid (来源: url)
provider-163: INFO 接口 js6_rpc 探测成功: unreadCount=8
```

#### ✅ 会话获取成功 + 接口未能解析未读数

说明 sid 已获取（证明 Cookie 传递可行），但接口返回格式需要进一步解析。

#### ❌ 会话获取失败（需要登录）

```
session:163: WARN 163 会话获取失败：返回了登录页面
```

此时需：
1. 在浏览器中打开并登录 mail.163.com
2. 刷新会话

#### ❌ sid 存在但探测被拦截

```
provider-163: WARN 接口 js6_rpc 被认证层拦截: FA_SECURITY
```

说明 sid 已过期或参数不正确，需要刷新会话。

## 调试开关

在设置页面中可调整以下参数：

| 设置项 | 说明 |
|--------|------|
| **日志级别** | `DEBUG` 记录所有请求/响应细节；`INFO` 记录关键步骤 |
| **检查间隔** | 定时自动检查的间隔（1~30 分钟） |
| **探测接口** | 选择要启用的探测接口（可按提供商分别勾选） |

## 常见问题

### Q: 探测结果中 `needsAuth=true` 且 `session.loggedIn=false`？
A: 说明无法从邮箱页面获取 sid。可能原因：
1. 浏览器中未登录 mail.163.com / mail.qq.com
2. 登录后未保持会话（可能被登出）
3. Cookie 未随请求携带（SameSite 限制）

### Q: 为什么需要"刷新会话"？
A: 会话 sid 有 30 分钟缓存。如果登录状态变化（如重新登录），需要手动刷新。

### Q: 探测返回 `FA_SECURITY` 或 `FA_UNAUTHORIZED`？
A: 163 的安全层或认证层拦截。可能 sid 已过期、参数不正确，或触发了风控。

### Q: QQ 探测返回登录页 HTML？
A: QQ 的会话未建立或 sid 无效。尝试点击"刷新会话"，并确认浏览器中已登录 QQ 邮箱。

### Q: 可以在真实邮箱账号上测试吗？
A: 可以，但建议使用测试邮箱，避免频繁请求触发风控。同时注意保持合理检查频率。
