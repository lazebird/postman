# 混合方案 v0.4.0 — 调试指南

## 架构概览

```
┌────────────────────────────────────────────────┐
│               混合方案调试流程                     │
├────────────────────────────────────────────────┤
│                                                │
│ 1. 同步会话（Options → 同步按钮）                  │
│    → 打开邮箱页 → 内容脚本提取 sid                 │
│                                                │
│ 2. SW 独立 API 检查（自动触发）                    │
│    → chrome.storage.session 读取缓存 sid          │
│    → 带 sid + Cookie 调 API → 获取未读数           │
│                                                │
│ 3. 失败回退                                      │
│    → 内容脚本 DOM 探测（需页面打开）                │
│    → 仍失败则提示重新同步                          │
│                                                │
└────────────────────────────────────────────────┘
```

## 调试入口

1. **Options → 混合方案·会话与探测**
   - 🔄 同步163/QQ会话：打开邮箱页提取 sid 并缓存
   - 📄 内容脚本探测：手动触发 DOM 探测
   - 🍪 诊断会话 Cookie：查看登录 Cookie 状态

2. **Popup → 状态 Tab**
   - 显示各提供商 sid 缓存状态（✅/❌）
   - 最近检查结果与方法

3. **Popup → 探测 Tab**
   - 全量检查 / 单个提供商测试
   - Cookie 诊断

4. **Service Worker 控制台**
   - `edge://extensions/` → 找扩展 → 点「Service Worker」
   - 查看 `[service-worker]` 和 `[provider-163]` / `[provider-qq]` 日志

## 关键日志模式

| 日志 | 含义 |
|------|------|
| `从内容脚本缓存 netease_163 sid (来自页面 URL)` | sid 获取并缓存成功 |
| `缓存 sid 状态: 存在` | SW 找到了缓存 sid |
| `SW API 探测成功: unread=8` | API 独立探测成功 |
| `缓存的 sid 已失效` | sid 超过 30 分钟 TTL |
| `163 会话已失效，清除缓存的 sid` | API 返回认证错误，sid 无效 |
| `内容脚本不可用` | 没有打开的邮箱页面标签 |

## 验证核心假设

1. **内容脚本能否提取 sid** → 看 Options 中同步后会话状态显示 sid ✅
2. **SW 能否用 sid 调 API** → 关掉邮箱标签，再点「测试」看结果
3. **Cookie 是否附带** → 看 Cookie 诊断结论和实际 API 响应
